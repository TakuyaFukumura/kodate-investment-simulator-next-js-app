# 戸建て投資シミュレータ開発計画書

## 1. 目的

公開されている無料の不動産投資シミュレーションで一般的な機能を参考にしつつ、戸建て投資の調達・運用・売却を段階的に試算できるアプリを開発する。最初から大規模な機能を作るのではなく、各フェーズで対象を絞り、要件定義・設計・実装・検証を繰り返して育てる。

この文書は開発の進め方と現時点の検討事項を管理する計画書である。計算式、入力項目、税務上の前提、画面仕様などの確定仕様は、各フェーズの要件定義書・設計書で決定する。

## 2. 現時点で確認できている方針

- 対象は戸建て投資とし、物件の調達から運用、売却までを段階的に扱う。
- リポジトリに配置したサンプルデータCSVを読み取り、初期値や試算例として利用する。
- 利用者が画面から値を設定し、設定した条件で計算を実行できるようにする。
- 計算結果はグラフなどを用いて視覚化する。
- テンプレート由来の既存機能は整理・削除する。ただし、ダークモード切り替えは維持する。
- 無料公開ツールの調査レポートに記載した機能を参考にする。調査対象の機能をすべて実装する前提にはせず、各フェーズで必要性を決める。
- 最初の計画作成時は文書化に専念し、アプリの実装や既存機能の削除には着手しない方針だった。フェーズごとの実装は、要件・設計を確定してから行う。

## 3. 開発サイクルと進捗管理

各フェーズで、以下のサイクルを一巡させる。検討事項が未決定のまま後工程に影響する場合は、原則として該当要件が決まるまで実装対象に含めない。進行上、暫定仕様で実装する場合は利用者未確認であることと見直し対象を意思決定記録に明記する。

1. **要件定義**：対象ユーザー、利用場面、対象範囲、入力・出力、受け入れ条件、対象外を決めて要件定義書を作る。
2. **設計**：画面、データ、計算の流れ、CSV仕様、エラー処理、テスト方針を決めて設計書を作る。
3. **小さく実装**：そのフェーズの受け入れ条件を満たす範囲だけ実装する。既存機能の置き換えは必要な単位に区切る。
4. **検証・レビュー**：計算例とテストで要件を確認し、画面の使いやすさや前提の分かりやすさを見直す。
5. **次フェーズへの反映**：未解決事項、改善点、実装済みの仕様を更新し、次フェーズの要件定義に引き継ぐ。

進捗はこの文書のフェーズ一覧で管理し、状態を `未着手`、`進行中`、`確認待ち`、`完了` のいずれかに更新する。フェーズの着手時に成果物の作成を開始し、完了時は受け入れ条件を確認して成果物へのリンクと完了日を記録する。意思決定は「検討事項一覧」に記録し、決定後は該当フェーズの要件定義書にも反映する。

### 共通の完了条件

- 要件定義書に、対象範囲、入力・出力、受け入れ条件、対象外が記載されている。
- 設計書に、画面・データ・計算処理・失敗時の扱い・検証方法が記載されている。
- 実装が合意済み要件と受け入れ条件を満たしている。
- 正常系に加え、境界値・入力エラー・CSV読み込み失敗など、対象となる異常系が確認されている。
- 利用者が計算の前提と結果の意味を確認でき、未実装の機能を実装済みと誤認しない。
- 変更内容、検証結果、残課題が記録されている。

各フェーズは、前フェーズの成果物と検討事項の決定状況を確認してから開始する。期間や作業量は、要件と優先順位を決めた後に見積もる。

### フェーズ1：サンプルCSVを使った基本試算

**目的**：CSVのサンプルを読み込み、画面で条件を設定して、物件購入前の基本的な収益性を試算できる最小の縦断機能を作る。

- 設計：CSVの列・文字コード・単位・必須項目・不正行の扱い、画面フォーム、計算モジュール、結果の表示方法を定義する。
- 実装：リポジトリ内のサンプルCSVを読み込み、選択または読み込んだ物件の値を画面に表示する。画面で値を編集して計算し、基本指標と結果の要約を表示する。
- 検証・レビュー：CSVの正常・欠損・不正データ、入力境界、既知の計算例を確認し、CSVの初期値と画面上の編集値が混同されないか評価する。

**対象機能（フェーズ1要件定義済み）**

- 物件価格、月額家賃、項目別取得費用、初回リフォーム費用、空室月数、年間運営費、借入額・金利・期間の入力
- 表面利回り、実質利回り、NOI、年間・月平均CF、年間返済額、DSCRの表示
- CSV・入力値の検証と、問題箇所を示すエラー表示

**成果物**：[要件定義書](フェーズ1要件定義書.md)、[設計書](フェーズ1設計書.md)、サンプルCSV、基本試算画面、計算ロジックとテスト。

**完了条件**：サンプルCSVから初期値を読み込め、画面上で値を変更して再計算でき、計算結果の前提と単位を確認できる。

- 実装：年次キャッシュフローを算出し、収入・運営費・返済・手残りの推移を表とグラフで示す。必要な戸建て固有の修繕入力を追加する。
- 検証・レビュー：複数年の手計算例、ローン完済年、空室や修繕費の変化、赤字となる条件を確認する。

**初期実装範囲**

- 年次収支・返済明細表、累計運営CF、年次CF・年末残債グラフ
- 固定金利・元利均等返済による返済額と残債の推移

**成果物**：フェーズ要件定義書・設計書、運用期間の計算仕様、年次結果画面、計算・グラフのテスト。

**完了条件**：設定した予測期間について各年の収入・費用・返済と手残りを追跡でき、変動条件が結果に反映される。

**仕様・実装**：[要件定義書](フェーズ2要件定義書.md)、[設計書](フェーズ2設計書.md)、`src/lib/projection.ts`、`src/app/components/ProjectionPanel.tsx`、`src/app/components/ProjectionCharts.tsx`

### フェーズ3：売却・投資全体の収益確認

**目的**：保有期間中の収支に売却時の収支を加え、調達から売却までの投資結果を比較できるようにする。

- 実装：売却条件を画面から設定し、保有年数別の売却後手残りと投資全体の収支を表示する。
- 検証・レビュー：保有期間、残債、売却価格が変わるケースを確認し、税や将来価格の概算表示が誤解を招かないかレビューする。

**候補機能（採否は要件定義で決定）**

- 売却年のNOIと想定売却利回りに基づく売却価格

- 保有期間別の累計キャッシュフロー、総投資損益、IRR等
- 税引前後の区分。税務計算を含める場合は計算対象と限界の明示

**決定済み**：売却年のNOIを想定売却利回りで割り、売却価格を算出する（Q18）。
**決定済み**：売却費用は項目別入力とし、譲渡税はフェーズ3の対象外とする（Q19）。費目の内訳は要件定義で整理する。
**決定済み**：保有年数ごとに年次運営CF・売却後手残り・総損益・単純損益率を表示し、IRRは後続フェーズで扱う（Q33）。
**決定済み**：売却費用は仲介手数料・印紙税・ローン完済手数料・その他を扱う（Q34）。仲介手数料は売却価格に連動して計算し、残り3項目は共通額とする（Q35）。

**決定済み**：想定売却利回りは未入力から開始し、入力後に売却試算を表示する（Q39）。

**仕様・実装**：[要件定義書](フェーズ3要件定義書.md)、[設計書](フェーズ3設計書.md)、`src/lib/exit.ts`、`src/app/components/ExitPanel.tsx`、`src/app/components/ExitChart.tsx`、売却計算・画面テスト。

## 5. CSV・画面・計算結果に関する初期設計方針

以下は今後の設計で決定するための初期案であり、確定仕様ではない。

### サンプルCSV

- リポジトリ内で用途が分かる場所に、実在個人の情報を含まない架空のサンプル物件データを配置する。
- CSVはサンプル条件の提供元とし、読み込んだ値を画面で確認・変更してから計算する。
- 画面上で変更した入力値を元のCSVへ書き戻すかどうかは未決定。安全な初期案は、元CSVを読み取り専用のサンプルとして扱うこと。
- 列名、文字コード、区切り文字、単位、必須列、入力検証、複数行を物件選択に使うかはフェーズ1で定義する。
- 読み込み失敗時は計算を続行せず、どの項目・行に問題があるか利用者に示す方針とする。具体的なエラー表示は設計で決める。

### 画面入力とグラフ

- 画面上の入力値が計算の根拠であることを明確にし、CSVの元データと利用者による変更を区別する。
- 金額、割合、期間などは単位と入力範囲を明示し、入力変更後に再計算する方法を定義する。
- グラフだけに依存せず、同じ情報を数値や表でも確認できるようにする。
- どのグラフをどのフェーズで導入するかは、表示する指標と利用場面を要件定義で決定する。

### 計算結果の説明

- 計算前提、適用した入力値、計算対象外を結果と一緒に確認できるようにする。
- 将来の家賃、空室、修繕費、金利、売却価格は仮定であり、結果は保証値ではないことを明示する。
- 税務や融資の扱いは要件確定前に断定せず、扱わない場合や概算に留める場合も明記する。
