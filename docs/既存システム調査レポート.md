# 既存システム調査レポート

## 調査概要

現在の画面、サーバー処理、データ保存、テストおよびプロジェクト資料を確認した。現状は、データベースに保存されたサンプル文言を画面に表示する最小構成のウェブアプリであり、戸建て投資の検討や収支計算を行う機能は実装されていない。

## 現在利用できる機能

- 画面を開くとサーバーから文言を取得し、取得中・取得成功・取得失敗の状態を表示する。
- 取得に失敗した場合はエラーを表示し、利用者が再試行できる。
- 画面上部の操作で明るい表示と暗い表示を切り替えられる。選択はブラウザー内に保存され、次回表示時にも引き継がれる。
- 画面は小さな画面にも対応するレイアウトを備えている。
- サーバーは、初回のデータベース利用時に保存先とテーブルを用意し、文言が未登録なら初期文言を登録する。画面には登録済みのうち最も新しい文言を返す。
- データベース処理に失敗した場合、サーバーはエラー応答を返す。

## 構成と確認できた品質対策

- 画面、サーバー側の取得処理、データベース操作が分かれている。
- 画面とサーバー間のデータ形式を検査し、不正な形式を成功扱いしない。
- 画面を離れた際に、進行中の取得処理を中断する。
- 画面の取得成功・失敗・再試行と、サーバーの正常・異常応答、データベース操作を対象とする自動テストがある。
- 静的解析、型検査、テスト、本番用ビルドを実行する設定がある。

## 投資シミュレーターとして不足している機能

現状、以下の機能やデータは確認できなかった。

- 物件の登録、編集、一覧表示、複数物件の比較
- 物件価格、取得時の諸費用、自己資金、借入条件などの入力
- 家賃収入、空室、運営費、修繕費、税金などを含む収支計算
- 月次・年次の資金繰り、借入返済、利回り、投資回収期間などの指標表示
- 保有期間や売却条件を考慮した出口の試算
- 条件を変えた複数シナリオの比較、計算結果の保存・出力
- 利用者や物件ごとのデータ管理

データベースに保存されているのは表示用の文言のみで、物件、費用、賃料、融資、試算結果に関するデータ構造はない。したがって、現行の画面やデータベースに投資計算を追加するだけでは足りず、入力項目、計算ルール、保存対象を新たに定義する必要がある。

## 開発に進む場合の検討事項

1. **試算の前提を決める** — 対象とする物件情報、取得費用、収入・支出、融資、保有期間、売却条件を定める。税金や将来予測を扱う場合は、適用条件と前提を明示する。
2. **計算指標と期間を決める** — 利用者に示す指標、月次・年次の粒度、端数処理、空室や費用の扱いなどを定義する。
3. **試算の保存・比較方法を決める** — 入力内容と計算結果を保存するか、複数条件を比較するか、データの出力が必要かを決める。
4. **入力画面と結果画面を設計する** — 入力漏れや不正値を防ぐ仕組みと、計算結果の根拠・注意事項を確認できる表示を用意する。

## 結論

現行システムから利用できるのは、サンプル文言の表示、表示モードの切り替え、取得失敗時の再試行といった基本機能である。戸建て投資の試算機能は存在しないため、まず計算対象・前提条件・出力指標を定義し、その後に物件データ、計算処理、入力・結果画面を設計する必要がある。
