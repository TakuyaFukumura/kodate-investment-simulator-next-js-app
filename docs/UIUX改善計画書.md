# UI/UX 改善計画書

## 1. 目的・利用者・前提

個人利用者が戸建て物件の購入候補を試算するとき、条件入力から3ケース比較、年次結果の確認までを迷わず進められるよう、UI（画面・操作部品）とUX（利用の流れ・理解しやすさ）の改善案をまとめる。

想定する基本フローは「サンプル物件を選ぶ → 基本条件を編集する → 運用・売却条件を調整する → 3ケースを比較する → 年次詳細を確認する → 必要に応じてJSON/CSVを出力する」。各段階で、現在のケース・条件の有効性・試算結果の位置づけが分かることを目標とする。

- **確認方法**：画面コンポーネント、スタイル、プロダクト要件、フェーズ4・5の設計・受け入れ条件をもとにしたソースレビュー。実装後にローカルブラウザーで幅705pxのライト・ダーク表示と、比較結果への移動を確認。
- **確認範囲**：初期画面、3ケース条件入力、比較結果、年次表、グラフ、ダークモード、入力エラー表示。
- **未実施**：375px・460px・768px・1280pxの個別表示確認、支援技術による操作確認、ユーザーテスト。実装後に改めて確認する。
- **基本方針**：計算式、入力項目、JSON/CSVの出力内容、試算条件を継続保存しない方針、既存の注意書きを維持する。操作ステップや表示を整理しても、詳細情報は削除せず必要な人が引き続き確認できるようにする。

## 2. 現状の評価

### 維持したい点

- 基準・楽観・慎重のケース切替と、入力値を保ったまま比較できる構成。
- ラベル付き入力、入力エラー表示、読み込み中・失敗時の表示、ダークモード。
- 横長の表・グラフを表示領域内でスクロールさせる対応と、表の見出し・キャプション。
- グラフに説明を添え、数値を表でも確認できる構成。

これらはプロダクト共通要件とフェーズ5の受け入れ条件にも含まれているため、改善後も回帰確認する。

## 3. 改善項目

優先度は、利用者の迷い・閲覧負荷への影響と、既存機能を維持したまま改善できる度合いを基準とする。

### P1：利用フローと画面の情報階層を明確にする

- **現状**：`ScenarioWorkspace` にケース切替、物件選択、基本試算、運用・修繕、売却条件、基本結果がまとまり、その後に比較指標、比較グラフ、年次詳細表が続く。ページ冒頭には概要があるが、入力・比較間の移動手段はなく、画面上の流れと利用者の「条件設定→結果確認」の流れがつながっていない。
- **根拠**：`src/app/page.tsx:60-70`、`src/app/components/ScenarioWorkspace.tsx:642-1050,1113-1300`
- **改善案**：
  1. 利用フローに沿って「物件・基本条件」「運用・売却条件」「ケース比較・詳細」のまとまりを明示する。
  2. 「条件を設定」「結果を比較」へのページ内ナビゲーションを設け、現在位置が分かるようにする。
  3. 選択中のケースと比較年、主要な結果を簡潔に確認できるサマリーを設ける。
  4. 詳細な修繕条件など、利用頻度の異なる情報は、初期画面の見通しを保つ段階的な表示を検討する。閉じた状態でも設定済みであることと入力エラーは分かるようにする。
  5. 小画面ではナビゲーションやサマリーが入力欄を圧迫しないよう、折り返し・配置を調整する。
- **完了基準**：
  - 利用者が物件・基本条件から比較結果までの手順と現在位置を把握できる。
  - 条件入力と比較結果を、長いスクロールを戻らずに行き来できる。
  - 現在編集中のケースと選択中の比較年を識別できる。
  - ケース切替や表示位置・詳細表示の切替で入力値が失われず、入力エラーも引き続き確認できる。

### P1：横長の年次表を段階的に読めるようにする

- **現状**：年次比較表は3つの識別列と21の指標列を持ち、最小幅は2200px。運用表は14列・1500px、売却表も12列・1550pxで、いずれも領域内スクロールを使う。
- **根拠**：`src/app/components/ScenarioWorkspace.tsx:1183-1290`、`src/app/components/ProjectionPanel.tsx:292-335`、`src/app/components/ExitPanel.tsx:197-247`
- **改善案**：
  1. まずNOI、運営CF、残債、売却後手残り、総損益など主要指標を確認できる表示を用意する。
  2. 全項目を確認する詳細表示は維持し、必要に応じて運営・融資・売却などの項目群ごとに切り替えて読めるようにする。
  3. 表の横スクロール領域が分かる視覚的な手がかりを追加し、ケース・年などの識別列はスクロール中も確認しやすくする。
  4. CSVの列・順序・値は変更しない。
- **完了基準**：
  - 375px、460px、768px幅でページ全体に不要な横スクロールが発生しない。
  - 主要指標を横スクロールなしで確認でき、詳細表示では現行の全項目を確認できる。
  - 表示切替はキーボードでも操作でき、スクロール中も行のケース・年を識別できる。
  - JSON/CSV入出力と年次データの内容に変更がない。

### P2：グラフの値とケース差を読み取りやすくする

- **現状**：各グラフには最大・最小値と基準線がある一方、中間目盛りや補助線はなく、正確な値は表で確認する案内になっている。比較グラフは色でケースを区別している。
- **根拠**：`src/app/components/ProjectionCharts.tsx:44-149`、`src/app/components/ExitChart.tsx:49-100`、`src/app/components/ScenarioComparisonChart.tsx:8-168`
- **改善案**：
  1. 金額・年の目盛りと補助線を加え、値の大きさやゼロとの差を見積もりやすくする。
  2. ケースの凡例をグラフに近接させ、色に加えて線種・マーカーなどでも識別できるようにする。
  3. グラフの単位・対象期間・算出できない値の扱いを一貫して示す。
- **完了基準**：
  - 主要な目盛り、ゼロ位置、単位、ケース凡例をグラフ内または隣接領域で確認できる。
  - 色だけに依存せず各ケースを識別できる。
  - 表の数値とグラフの表示が一致し、狭い画面でもグラフ領域内で閲覧できる。

### P2：入力エラーを入力欄と結び付ける

- **現状**：無効入力には `aria-invalid` があり、エラー文も近くに表示される。一方、確認した入力欄ではエラー文を `aria-describedby` で関連付けていない。
- **根拠**：`src/app/components/ScenarioWorkspace.tsx:763-811,844-870`、`src/app/components/ProjectionPanel.tsx:111-150,200-235`、`src/app/components/ExitPanel.tsx:128-158`
- **改善案**：
  1. エラー文に一意なIDを付け、該当入力欄の `aria-describedby` から参照できるようにする。
  2. 複数ケースにエラーがある場合、ケース名・項目名から該当箇所へ移動しやすい要約を検討する。
  3. キーボードフォーカスが見えること、エラー発生時に色だけで状態を伝えていないことを確認する。
- **完了基準**：
  - 支援技術で入力欄に移動した際、無効状態と具体的なエラー理由を確認できる。
  - エラー要約を設ける場合は、対象ケース・項目を特定でき、該当入力欄へ移動できる。
  - 既存の入力検証・計算抑止・ケース切替の挙動を維持する。

### P3：操作状態と視覚スタイルを揃える

- **現状**：ページは slate 系の背景・文字色と emerald 系のアクセントを使う一方、ヘッダーは gray 系の背景・境界色を使う。入力欄・ボタンのスタイルも各コンポーネントに個別定義されており、hover・focus・disabled・invalid の状態を一貫して把握しづらくなる可能性がある。
- **根拠**：`src/app/page.tsx:63-70`、`src/app/components/Header.tsx:30-52`、`src/app/components/ScenarioWorkspace.tsx:143`、`src/app/components/ProjectionPanel.tsx:22`、`src/app/components/ExitPanel.tsx:15`
- **改善案**：
  1. slate・emerald を基準にヘッダー、入力欄、ボタン、カードの状態色を揃える。
  2. 余白、角丸、境界線、フォーカスリング、押下・無効状態の共通ルールを定め、主要画面に適用する。
  3. ライト・ダーク両テーマで文字と状態表示の読みやすさを確認する。
- **完了基準**：
  - ヘッダーと本文の色・状態表示に一貫性がある。
  - 入力・ボタンの通常、hover、focus、disabled、invalid の見え方が揃っている。
  - ライト・ダークの両方でコントラストとフォーカス表示を確認できる。

## 4. 推奨する実施順

1. **UXフローと情報設計**：条件入力・比較結果への移動、段階的な情報表示、ケース・年のコンテキスト表示を整える。
2. **レスポンシブな結果閲覧**：主要指標と詳細表を段階的に見せる。既存の全項目とCSV出力を維持する。
3. **理解しやすさとアクセシビリティ**：グラフの目盛り・凡例と、入力エラーの読み上げ・移動を改善する。
4. **UI一貫性**：共通の色・余白・操作状態を揃える。

各段階で、375px・460px・768px・1280pxの画面幅、ライト・ダークテーマ、キーボード操作、既存テストを確認する。特に表・グラフについては、ページ全体の横はみ出しがないことと、必要なデータが隠れず閲覧できることを確認する。

## 5. 今回の対象外

- 投資計算式、初期値、検証範囲、税務上の扱いの変更。
- 新しい投資指標や外部データ連携の追加。
- 試算条件・計算結果の継続保存。
- データ出力形式や既存注意書きの変更。
