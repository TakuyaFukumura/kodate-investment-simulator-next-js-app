- `src/app/components/ScenarioWorkspace.tsx`：3ケースの編集状態を保持し、既存の投資・年次運用・売却計算を呼び出す。JSON/CSVのファイル操作もここで行う。

## 3. ケース状態と計算

- ケースIDと表示順は `baseline`（基準）、`optimistic`（楽観）、`cautious`（慎重）に固定する。
- 初回はサンプルCSVの先頭物件を基準とし、楽観・慎重にはその条件を複製する。各ケースは画面入力値を個別に保持し、切り替え後も編集を維持する。
- 保有期間は共通条件として管理する。家賃変化率、運営費変化率、修繕予定、売却条件、基本試算条件は各ケースが独立して保持する。
- 売却利回りは既存仕様どおり初期未入力とし、3ケースすべての条件が有効になるまで比較結果とファイル出力を無効にする。
- 画面入力は編集中の空欄・不正値を保つため文字列で保持し、既存バリデーターを通過したケースだけ計算する。
- 保有年選択の初期値は有効な共通保有期間の最終年とする。期間を短縮したとき、選択年は新しい最終年に合わせる。
- 3ケースの主要指標、グラフ、年次表は同じ年次運用・売却結果を参照する。総損益を算出できない年はグラフの点を描かず、表は「—」、CSVは空欄とする。

## 4. JSON条件ファイル

### 4.1 v1構造

以下は構造の例であり、実ファイルでは `investment` と `exit` を含む各ケースの全必須項目を出力する。

```json
{
  "formatVersion": 1,
  "holdingYears": 30,
  "cases": {
    "baseline": {
      "propertyName": "サンプル物件",
      "investment": {},
      "projection": {
        "annualRentChangePercent": 0,
        "annualOperatingCostChangePercent": 0,
        "repairEvents": []
      },
      "exit": {}
    },
    "optimistic": {},
    "cautious": {}
  }
}
```

- `investment` は `InvestmentInput` の全数値項目、`projection` は保有期間以外の `ProjectionAssumptions`、`exit` は `ExitAssumptions` の全項目を持つ。
- 各ケースに物件名を保存し、同梱CSVのIDや行に依存しない。
- エクスポート前に3ケースすべての入力を検証する。JSONはUTF-8、整形済みテキストとする。
- インポート時はトップレベル構造、整数の形式バージョン、全ケースの必須キー・型・数値検証を先に完了する。追加キーは将来拡張を妨げないよう無視する。
- 未対応バージョン・構造不正・ケース入力不正を区別して表示する。入力エラーはケース名・項目名・既存バリデーションの原因を示す。全件検証後にのみ一括反映する。
- ファイル選択ボタンでJSONを読み込む。成功時に3ケースを置き換え、失敗時は現在の編集内容を一切変更しない。
- ファイル名は `戸建て投資条件_YYYY-MM-DD.json` とし、実行端末のローカル日付を使う。

## 5. 年次結果CSV

### 5.1 列順

1. ケース
2. 物件名
3. 年
4. 満室想定家賃（万円）
5. 空室損失（万円）
6. 実効家賃（万円）
7. 運営費（万円）
8. NOI（万円）
9. 修繕費（万円）
10. 元金返済（万円）
11. 利息返済（万円）
12. 年間返済額（万円）
13. 年末残債（万円）
14. 年次運営CF（万円）
15. 累計運営CF（万円）
16. DSCR（倍）
17. 売却価格（万円）
18. 仲介手数料（万円）
19. 印紙税（万円）
20. ローン完済手数料（万円）
21. その他売却費用（万円）
22. 売却後手残り（万円）
23. 総損益（万円）
24. 単純損益率（%）

- 行順は年の昇順、同一年は基準・楽観・慎重の順とする。
- UTF-8 BOM付き、カンマ区切り、CRLF改行、ヘッダー行ありとする。文字列セルはRFC 4180に従い必要時に引用符で囲み、表計算ソフトの数式として解釈され得る先頭文字は無害化する。
- 金額・DSCR・割合は数値のみ、小数第2位までとし、通貨記号・桁区切りを付けない。`null` の計算値は空欄とする。
- 売却利回り未入力など、いずれかのケースの入力が無効な間はCSV出力を無効化し、該当条件の修正を促す。
- ファイル名は `戸建て投資年次結果_YYYY-MM-DD.csv` とし、実行端末のローカル日付を使う。

## 6. 画面構成

- 条件カードに基準・楽観・慎重のタブ、物件名、サンプル物件選択、基本試算・運用・売却条件を配置する。保有期間は3ケース共通の入力とする。
- 選択ケースの基本試算指標とウォーターフォールを条件編集に併設し、既存のフェーズ1表示を維持する。
- 条件カードにJSON出力、JSON取り込み、CSV出力の操作を配置する。全ケースが有効でない場合、JSON/CSV出力を無効にし、理由を表示する。
- 比較結果は主要指標、総損益折れ線グラフ、年次詳細表の順に表示する。
- 主要指標は選択年を切り替えられるようにし、NOI・年間運営CF・売却後手残り・総損益・単純損益率を3ケース横並びで示す。
- 年次詳細表はCSVと同じ24列で、年順・ケース順に表示する。ケース・物件名・年の列を横スクロール中も識別しやすくし、画面幅を超えた場合は横スクロールする。
- 選択ケースの年次CF・残債グラフを年次詳細表の後に表示し、既存のフェーズ2表示を維持する。
- 選択ケースの累計運営CF・最終年CF・期末残債のサマリーも表示する。
- 入力エラーがあるケースはケース名と項目別エラーを示し、そのケースの結果値は表示しない。
- JSON・CSVはブラウザー内で生成してダウンロードし、サーバーや継続ストレージへ送信・保存しない。
- 既存のダークモードを維持する。

## 7. テスト設計

- JSON：有効データの往復、形式バージョン不一致、必須ケース欠落、入力値エラー、修繕予定エラー時のケース・項目特定。
- CSV：ヘッダー・列順、3ケースと年の並び、金額精度、BOM/CRLF、引用符・カンマを含む物件名、売却不可およびDSCR算出不可時の空欄。
- 日付：ローカル日付でJSON/CSVのファイル名を生成する。
- 画面：ケース切り替え後の編集値維持、複製後の独立編集、共通保有期間、3ケース比較、JSON失敗時の状態維持、無効入力時のダウンロード抑止。
- 回帰：既存の投資・運用・売却計算、サンプルCSV読込、ダークモード。
